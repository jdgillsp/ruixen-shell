## 1. Evidence that exists in the repository today

- `bars/widgets/ruixen.notch/ubj-today.py` (added in `500961f`, extended in
  `b39fb44`) is a read-only helper. It only issues GET requests, only to
  loopback `127.0.0.1:<api_port>`, with no proxy and redirects refused. It
  reads `/api/office?days=7`, `/api/autonomy/priorities?limit=5` and
  `/api/backlog/board`, and prints a single JSON snapshot to stdout. It
  takes `api_port`/`api_key` from `~/.config/UseBestJudgment/config.json`
  (or `UBJ_CONFIG_PATH`/`UBJ_API_PORT`) and scrubs the key from error text.
  It writes no state files.
- `bars/widgets/ruixen.notch/UbjTodayPanel.qml` is the panel. It polls the
  helper through a `Process` every 15 s, and only while
  `active && visible`. A read is killed after 6 s and the panel shows "UBJ
  status read timed out". It keeps the last snapshot in memory only. It
  shows a "UBJ Offline" header plus the error text and hides the
  online-only sections when `online` is false. It shows an
  `updated hh:mm:ss` timestamp. It renders:
  - stat pills: waiting, working, failing, unpushed;
  - an ATTENTION list: waiting sessions, failing checks, unpushed commits,
    capped at 6;
  - a COMPUTE PLAN card: budget, mode, eligible agents with headroom, up to
    4 allocated slots with project/agent/title;
  - a backlog "Board:" line: ready/blocked/held/done/flagged.
- `bars/widgets/ruixen.notch/KanbanContent.qml` adds a "UBJ Today"
  view-mode toggle. It mounts `UbjTodayPanel` with
  `active: root.active && root.viewMode === "ubj"`.
- `tests/notch-ubj-today.sh` (registered in `tests/run-all.sh`) checks the
  helper against a local mock HTTP server. It covers an authenticated
  online snapshot, a 401 that reports offline without leaking the key, and
  a closed port that reports offline. It also greps the two QML files for
  the polling and active guards.

## 2. What is missing, per declared acceptance criterion

**Criterion A: "Shows UBJ's current next actions, branch/autonomy verdicts,
and exceptions."**
- **Next actions:** partly covered. The panel shows allocated compute slots
  from `/api/autonomy/priorities`. Nothing shows that these are what UBJ
  means by "next actions". The helper does not read `get_next_work` or a
  Today endpoint.
- **Branch/autonomy verdicts:** not found. I saw no consumption of
  automerge or iteration verdicts, for example `verified_but_unmerged` or
  automerge blockers. The helper builds `compute.admission` (the nightly
  admission detail), but `UbjTodayPanel.qml` never renders it.
- **Exceptions:** partly covered. Waiting, failing and unpushed rooms are
  shown, plus a flagged backlog count.

**Criterion B: "Holds no copy of project state; stale or unreachable UBJ is
shown as such."**
- No persisted copy: supported by the source. I found no state-file
  writes, only a transient in-memory last snapshot.
- Unreachable/timeout/401: handled in the source and in the mocked test.
- **Gap — partial failure is not shown as stale.** If `/api/office`
  succeeds but `/api/autonomy/priorities` or `/api/backlog/board` fails,
  the helper silently returns `{}` for that section. The panel then shows
  "Budget: 0/0 · quota_weighted" and "Eligible: none", which looks like
  real data rather than "unavailable".
- **Gap — mocked contract only.** The test mock does not serve
  `/api/backlog/board`, which returns 404, so the backlog path is never
  asserted. Nothing compares the field names the helper expects
  (`totals`, `rooms`, `archive`, `supply`, `allocation`, `counts`,
  `columns`) against the real UBJ API responses.
- **Gap — no age-based staleness.** The panel only shows the time of the
  last update. It never marks a snapshot stale by age.

**Runtime gap.** I found no recorded live check: no `omarchy restart
shell`, journal check, or screenshot of the panel against a running UBJ. The
rule in `AGENTS.md` §8 says this check is required for QML changes.
